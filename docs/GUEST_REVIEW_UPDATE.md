# Mellon — гостевой доступ и проверка новых пользователей

## Установка

1. Остановите запущенный Flutter клавишей `q` в его терминале.
2. Скачайте `update_mellon_guest_review.py` в «Загрузки» и выполните:

```bash
cd ~/Desktop/moy_prihod
python3 ~/Downloads/update_mellon_guest_review.py
flutter analyze
flutter test
```

Установщик создаёт резервную копию рядом с проектом. Настройки подключения, существующие миграции и исправления ввода пароля сохраняются. Неизвестные локальные изменения останавливают установку до записи файлов. Включены последние исправления открытия фотографии клуба в браузере и теста выхода из клуба, если они ещё не установлены.

3. В Supabase → SQL Editor откройте новый запрос, вставьте **весь** `mellon_guest_review.sql` и нажмите Run. Нужна ранее установленная миграция `mellon_club_live.sql` (020). Новый файл — миграция 021. Повторное выполнение того же SQL безопасно. Не заменяйте отдельные строки в старых миграциях.
4. Если клубов несколько, под суперадмином откройте **Управление → Молодёжные клубы → Клуб для новых заявок** и выберите клуб. При единственном доступном клубе выбор автоматический. Настройка влияет на новые заявки; уже направленные заявки не перемещаются.

Если клуб пока не выбран или клубов нет, пользователь остаётся в ожидании. Суперадмин получает уведомление о настройке приёма; после выбора клуба ожидающие заявки направляются туда автоматически. Случайный клуб не выбирается.

## Что изменилось

- Новая регистрация не выдаёт членство. До подтверждения email сохраняется гостевой доступ; после подтверждения — «Ожидание проверки».
- Подтверждённые существующие аккаунты, роли и членства не переводятся на повторную проверку. Старые неподтверждённые регистрации без действующих прав проходят проверку после подтверждения email.
- Гостю доступны «Общая», «События», «Помощь» и карта. Кнопка «Молодёжный клуб» остаётся в основной навигации: без входа открывает регистрацию, для гостя в аккаунте — модальное окно статуса с фоном регистрации. Вкладка «Клубы» в ленте и каталог гостю скрыты. Прямые ссылки и запросы к базе тоже не открывают внутренние разделы.
- Индикатор на колокольчике отражает непрочитанные уведомления. Админ нужного клуба и суперадмин получают имя заявителя и название клуба. Существующее право руководителя рассматривать заявки сохраняется.
- Уведомление открывает заявки именно нужного клуба. Карточка заявителя показывается первой и выделяется спокойным цветом. Если заявка уже рассмотрена, показывается понятное сообщение.
- «Принять»: статус «Проверен», доступ к одобренному клубу. «Отклонить»: статус «Проверен», гостевой доступ и текст «Доступ к молодёжному клубу пока не открыт».
- Результат сохраняется в базе и приходит пользователю в уведомлении. Перезагрузка страницы для смены статуса не нужна. При временной потере соединения остаются повторные фоновые проверки доступа и обновление после возврата в приложение.
- Решение не удаляет аккаунт и не меняет права в других клубах. Ручное глобальное ограничение «Гость» не снимается одобрением автоматически. Суперадмин может изменить глобальный доступ после завершения проверки через существующее управление ролями. До проверки интерфейс сообщает, что сначала нужно рассмотреть заявку.
- Новые роли не добавлены. Проверки полномочий, подтверждения email и повторного решения выполняются на сервере в транзакции.

## Проверки

В рабочей среде выполнены **19 проверок PostgreSQL/PGlite**, включая существующие чаты, непрочитанные сообщения, права редактирования фото, выход из клуба, проверку регистрации, принятие/отказ, повторное решение, межклубную изоляцию и сохранение старых ролей. Проверены синтаксис Dart и ссылки импортов.

Flutter SDK в среде подготовки отсутствует: `flutter analyze`, widget-тесты, браузерный интерфейс и реальная доставка Supabase Realtime здесь не запускались. Добавлены/обновлены тесты гостевой навигации, перехода по уведомлению и смены статуса. Запустите анализатор и весь набор тестов командой выше. Отдельно новые проверки:

```bash
flutter test test/guest_review_test.dart test/design_navigation_test.dart test/club_navigation_test.dart --reporter expanded
```

После установки SQL проверьте с новым тестовым аккаунтом: подтверждение email → ожидание → уведомление администратору → отказ. Отдельным новым аккаунтом проверьте принятие. Действующий участник должен сохранить свой доступ.

## Компактное окно и анимированные песочные часы

Окно статуса теперь подстраивается под содержимое: большая пустая область убрана, кнопка «Понятно» расположена под карточкой. На узком экране или при увеличенном тексте содержимое прокручивается; крестик остаётся доступен сверху. Формы регистрации, входа и восстановления сохраняют прежние размеры.

«Ожидание» оформлено в светлой плашке с тонкой голубой рамкой. Заголовок — «Заявка на проверке», затем пояснение и более мелкая подпись о доступных разделах. Песок плавно пересыпается, после чего часы медленно переворачиваются. Анимация декоративная, не показывает оставшееся время проверки. Она останавливается при настройке уменьшения движения, на неактивном экране и при закрытии окна. Храм и прежняя скорость облаков сохранены.
