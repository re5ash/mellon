# Обновление: управление приходами, публикациями и заявками

## Установка в существующий проект на Mac

1. Скачайте `update_moy_prihod_admin.py` и переместите его в `/Users/president/Desktop/moy_prihod`, рядом с `pubspec.yaml`.
2. Откройте эту папку в VS Code. Все следующие команды выполняются **во встроенном терминале VS Code**, где приглашение заканчивается `moy_prihod %`.
3. Если там работает Flutter, нажмите `q` и дождитесь приглашения терминала. Затем выполните:

```bash
python3 update_moy_prihod_admin.py
flutter analyze
flutter test
```

Запускайте следующую команду после успешного завершения предыдущей. Если установщик сообщает конфликт, ничего не заменяйте вручную: сохраните вывод и пришлите его для подготовки совместимого обновления. Если analyze или тесты сообщают ошибку, сначала исправьте её.

4. После успешных проверок в том же терминале:

```bash
npx supabase db push
```

Для вашего уже привязанного проекта должна предлагаться только новая миграция `202609100007_administration.sql`. При таком списке подтвердите `Yes` и дождитесь `Finished supabase db push`. Если список другой, сначала проверьте, какой проект привязан и какие миграции уже применены. Не запускайте `db reset`.

5. В том же терминале запустите приложение:

```bash
flutter run -d chrome --web-port=8080 --dart-define-from-file=config/development.json
```

6. В открывшемся **Chrome, внутри приложения**: «Ещё → Управление → Тестовый приход». Здесь появятся «Редактировать приход», «Заявки участников», «Создать публикацию» — в зависимости от прав аккаунта.

## Первая проверка интерфейса

- Откройте «Создать публикацию», заполните заголовок и текст. По умолчанию запись — приватный черновик.
- Для общей ленты выберите «Кому доступна → Общая лента», «Статус → Опубликовано», нажмите «Опубликовать». Приход должен быть опубликован в каталоге.
- Вернитесь в «Лента»: запись должна появиться. Для приватной записи выберите «Только приход» и проверьте её в «Mellon» под активным участником.
- Откройте запись снова, измените текст, сохраните. Статус «Архив» убирает запись из ленты; физического удаления в этом обновлении нет.
- «Заявки участников» показывает ожидающие заявки. У вашего аккаунта уже активное членство, поэтому он не появится в этом списке. Нужна заявка другого тестового пользователя. Отклонение требует подтверждения, одобрение выполняется сразу.
- «Создать приход» находится на главной странице управления и доступно по глобальному праву `parishes.manage`.

## Что меняется и сохраняется

Обновляются только перечисленные в установщике исходники, новая миграция, тесты и документация. Установщик сначала проверяет все файлы и только потом пишет изменения. Отличия в исходниках и миграциях приводят к остановке без записи. Если отличается только локальный отчёт `docs/VERIFICATION.md`, установщик сохраняет его без изменений и продолжает обновление приложения; об этом выводится отдельное сообщение.

Резервная копия заменяемых файлов создаётся рядом с проектом, в `moy_prihod_update_backups/<дата>/`. Она находится вне Flutter-проекта, чтобы analyzer не проверял старые Dart-файлы. В копии есть список новых файлов. При ошибке записи установщик восстанавливает прежние файлы. Повторный запуск уже установленного обновления безопасен.

Не изменяются `config/development.json`, Android runner, web-ресурсы, `pubspec.lock`, авторизация CLI или существующие записи базы. SQL добавляет колонку автора создания, индексы и четыре RPC; данные приходов, членства и ролей сохраняются. Серверные ключи не добавляются в клиент.

## Серверные права и ограничения

| Действие | Разрешение |
|---|---|
| Создать приход; изменить его видимость в каталоге | `parishes.manage`, глобально |
| Изменить описание, адрес и способ вступления | `parish.manage`, выбранный приход |
| Создать/изменить/публиковать/архивировать запись | `posts.manage`, выбранный приход |
| Посмотреть и обработать заявки | `memberships.manage`, выбранный приход |

Проверки используют ключи прав, а не название роли. Supabase проверяет права на сервере при каждом RPC. Администратор видит отображаемое имя заявителя, ID заявки/пользователя и дату; почта, телефон и дата рождения этим RPC не выдаются. Закрытый каталог профилей не становится публичным.

При изменении записи другим администратором появляется сообщение о конфликте: вернитесь к списку, обновите его и откройте запись заново. Повтор создания из той же формы не создаёт дубль. После неопределённого сетевого результата повтор возвращает первоначально созданную запись; дальнейшие изменения выполняются через её редактирование.

Новый город создаётся по названию и стране. Эта версия использует исходные настройки проекта `RU` / `Europe/Kaliningrad`; сервер допускает другие страну и IANA timezone через параметры RPC. Выбор страны/часового пояса и изменение города существующего прихода в форме пока не реализованы. Координаты существующих приходов сохраняются.

Это обновление добавляет управление текстовыми публикациями и заявками. Редакторы событий/помощи, медиа, роли/аудит в UI, исключение/бан участника, полный профиль и карта остаются следующими этапами.
