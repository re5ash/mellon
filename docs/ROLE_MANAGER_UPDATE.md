# Mellon — управление ролями в одном окне

## Установка на текущий проект

1. Остановите приложение клавишей `q` в терминале, где запущен Flutter.
2. Скачайте **update_mellon_role_manager.py** в «Загрузки» и выполните:

```bash
cd ~/Desktop/moy_prihod
python3 ~/Downloads/update_mellon_role_manager.py
flutter analyze
flutter test
```

Установщик проверяет совместимость файлов до записи и делает резервную копию рядом с проектом. Локальные настройки Supabase и исправления полей входа сохраняются. Если файлы отличаются от поддерживаемой версии, запись не начинается: пришлите вывод терминала.

3. В Supabase вашего проекта откройте **SQL Editor → New query**. Вставьте **весь** файл `supabase/updates/role_manager.sql` из обновлённого проекта (либо скачанный `mellon_role_manager.sql`) и нажмите **Run**. Это один и тот же SQL. Его нужно применять после предыдущего обновления заявок в клуб. Повторное выполнение этого файла безопасно; он сообщает, что уже установлен. Предыдущие SQL-обновления повторять не нужно.
4. Запустите приложение:

```bash
flutter run -d chrome --profile --web-port=8080 --dart-define-from-file=config/development.json
```

При использовании Supabase CLI вместо SQL Editor примените новую миграцию `202609120015_role_manager.sql` штатным способом. Не устанавливайте одну миграцию одновременно двумя способами.

## Как работает экран

**Управление → Роли → человек → глобальный доступ → клуб → роль → Сохранить изменения.**

На широком экране список людей расположен слева, редактор справа. На телефоне выбор человека плавно открывает его карточку внутри той же модалки; стрелка возвращает список. Поиск работает по имени. Имя, email, названия клубов и пояснения переносятся; содержимое прокручивается. Все цвета и карточки используют текущую тему приложения.

Есть только пять названий ролей:

| Блок | Выбор | Результат |
| --- | --- | --- |
| Всё приложение | Суперадмин | Полное управление приложением и клубами |
| Всё приложение | Участник | Обычный доступ к аккаунту; права клубов задаются отдельно |
| Всё приложение | Гость | Общая лента, карта и регистрация; закрытые права временно не действуют |
| Молодёжный клуб | Руководитель | Руководство выбранным клубом |
| Молодёжный клуб | Модератор | Модерация и работа с событиями выбранного клуба |
| Молодёжный клуб | Участник | Обычное участие в выбранном клубе |

«Гость» внутри клуба не предлагается. Перед сохранением нового гостевого ограничения нужно отметить подтверждение. Аккаунт, профиль, участие и роли других клубов не удаляются. После возврата глобального доступа «Участник» сохранённые клубные роли снова действуют. Для регистрации другого аккаунта ограниченный пользователь явно выходит из текущего аккаунта кнопкой в гостевом экране.

Выбор клуба сам по себе ничего не назначает. Можно изменить роли нескольких клубов, затем сохранить их одной кнопкой. Повторное открытие другого клуба сохраняет сделанный выбор до общего сохранения. Закрытие с несохранённым выбором предлагает остаться или отменить изменения внутри этого же окна.

Суперадмин видит всех людей и все клубы. Руководитель видит управляемых участников, назначает модератора или участника в своём клубе; менять глобальные права, назначать/понижать руководителей и редактировать чужие клубы он не может. Для назначения руководителя требуется суперадмин либо ранее выданное право администратора соответствующего прихода. Опубликованные чужие клубы видны в списке как недоступные для изменения; чужое членство не раскрывается.

Блок «Приход» и конструктор пользовательских ролей убраны из нового сценария. Ранее выданные права администратора прихода сохраняются: обновление не отбирает их массово. Если такие права дополнительно действуют у человека, редактор показывает пояснение. Выбор роли клуба меняет только его клубные назначения; глобальный суперадмин и прежние права более широкой области продолжают давать соответствующий доступ. «Актив» остаётся отдельным статусом на экране участников.

## Серверное поведение

- Один человек может участвовать в нескольких клубах, в том числе при разных приходах. Членство в приходе не создаётся автоматически. В «Молодёжном клубе» появляется выбор своего клуба; в профиле перечисляются клубы.
- Сохранение — одна транзакция с проверкой всех назначений до записи. Изменение роли одного клуба не сбрасывает другие клубы, статус актива и настройки профиля.
- Если права параллельно изменены другим администратором, устаревшее окно не перезапишет их. Введённый выбор остаётся на экране, можно загрузить актуальные права.
- Повтор запроса после потери ответа не дублирует запись. Нельзя снять права последнего действующего суперадмина.
- Гостевое ограничение проверяется в базе при обращении к закрытым данным и действиям. Интерфейс обновляет сведения о доступе примерно каждые 30 секунд и при возвращении в приложение. Авторизация по паролю и восстановление аккаунта не меняются.
- Профильные фото загружаются через временные ссылки только для уполномоченного управляющего. Публичного доступа к хранилищу фото не добавлено.

## Проверка после установки

1. Под суперадмином откройте «Управление → Роли». Найдите участника по имени.
2. Выберите два разных клуба и разные роли. До сохранения права не меняются. Сохраните и откройте карточку снова: обе роли должны остаться.
3. Измените только одну роль; вторая должна сохраниться. Проверьте переключение клубов у этого участника.
4. На отдельном тестовом аккаунте включите «Гость» с подтверждением. В его сессии должны остаться общая лента, карта и гостевой экран регистрации; чаты и управление недоступны. Верните «Участник» и проверьте восстановление прежних клубных прав.
5. Под руководителем проверьте назначение модератора своего клуба и отсутствие возможности менять глобальный доступ или чужой клуб.

Не используйте единственного суперадмина для проверки гостевого режима: сервер намеренно запрещает его понижение.

## Что проверено при подготовке

Выполнены интеграционные проверки в локальном PostgreSQL/PGlite с тестовыми схемами Auth/Storage: новые права и несколько клубов, существующие ограничения RLS, чаты/модерация/профиль и заявки. Проверен повторный запуск SQL, совместимость установщика, резервная копия и отказ при конфликтующих файлах. Выполнены форматирование и синтаксический разбор изменённых Dart-файлов.

Добавлены Flutter-тесты окна: независимые черновики клубов, подтверждение гостя, повтор сохранения после ошибки, защита от двойного нажатия, узкий экран с крупным текстом, поиск и смена аккаунта.

Flutter SDK в среде подготовки недоступен, поэтому `flutter analyze`, `flutter test` и визуальная проверка окна в Chrome здесь не запускались. Их нужно выполнить в вашем проекте командами выше. Проверки PGlite не заменяют проверку живого Supabase Auth/Realtime и браузера.
