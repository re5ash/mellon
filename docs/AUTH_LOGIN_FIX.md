# Исправление зависания входа

## Восстановление браузерного ввода после отказа входа — 11.09.2026

Два отчёта пользователя с версией stability_fix_83 показали: после клика
браузерное поле пароля потеряло фокус, а к моменту отчёта ранее активные
password-input были удалены из DOM. Последующие клавиши приходили другому
элементу, без событий beforeinput/input. Страница продолжала работать;
в последнем отчёте отдельное проверочное поле получило 7 событий ввода.
Это указывает на невосстановленное подключение ввода; точный дефект внутри
браузера/движка Flutter здесь не воспроизведён.

Изменения:

- Основная кнопка помещена в TextFieldTapRegion: клик мышью по ней больше
  не считается кликом вне поля, в том числе во время ожидания ответа.
- После отказа входа прежние состояния полей заменяются новыми. Старые
  подключения ввода освобождаются, а фокус возвращается после завершения кадра.
- Контроллеры с текстом сохраняются. Выделение не сбрасывается на весь текст.
  Если пользователь исправлял почту до ответа сервера, ввод остаётся в почте.
- Повторная отправка защищена на время восстановления. Возврат фокуса
  отменяется после ухода со страницы или переключения режима формы.
- Сохраняются тайм-аут, проверка пароля на сервере, защита от одновременных
  запросов и переход после успешного входа.

Обновлены проверки нажатий: вместо касания используется PointerDeviceKind.mouse.
Добавлены две проверки потери подключения тестовой клавиатуры без уведомления
Flutter — для пароля и для почты. После отказа проверяется новое подключение,
сохранение текста/курсора, удаление и ввод через канал без tester.enterText().
Это тесты протокола, они не заменяют проверку настоящего DOM в Chrome.

Причина различия касания и мыши описана в документации Flutter:
[TextField.onTapOutside](https://api.flutter.dev/flutter/material/TextField/onTapOutside.html),
[TextFieldTapRegion](https://api.flutter.dev/flutter/widgets/TextFieldTapRegion-class.html).

После успешного запроса входа приложение заново читает сессию и явно
переходит на разрешённую страницу назначения. Время ожидания запроса
ограничено 30 секундами. Поля остаются доступными во время запроса;
кнопка отправки блокируется, чтобы не отправлять запрос дважды.
Сетевой тайм-аут не означает отказ сервера: при нём также перечитывается сессия.

Симптом пользователя: после неверной ссылки и повторного входа форма
оставалась заблокированной, хотя обновление браузера показывало аккаунт.
Точная причина в браузере не воспроизведена; исправлены зависимость перехода
только от события сессии и отсутствие ограничения ожидания.

## Исправление редактирования после неверного пароля

Пользователь подтвердил: правильный пароль открывает приложение без
обновления страницы; после неверного пароля ввод в браузере застревает.
Убрано переключение enabled у полей. Enter сохраняет фокус, а после
ошибки курсор возвращается в поле пароля. При редактировании ошибка скрывается.
Данные отправляемого запроса фиксируются до ожидания ответа.

Прежний тест возвращал ошибку мгновенно и повторно активировал поле через
tester.enterText(), поэтому не проверял сохранение подключения клавиатуры.
Добавлены проверки задержанного invalid_credentials: отдельно Enter и кнопка,
затем очистка через уже открытое подключение ввода и успешный повторный вход.
На реальном браузере это исправление ещё предстоит подтвердить.

## Устойчивость формы при быстрых повторных нажатиях

На Mac пользователя прежний вариант прошёл 81 тест, но ввод в Chrome
иногда переставал работать даже после перехода между полями. Ответ сервера
при этом: invalid_credentials. Это не токен, а отказ входа.

В следующем исправлении:
- Только блок действий подписан на состояние запроса. Поля не перестраиваются
  при загрузке, ошибке и её очистке.
- Ошибка отображается под основной кнопкой и больше не сдвигает её.
- Ввод без показанной ошибки не создаёт лишних обновлений состояния.
- Запоздавший отказ не переводит фокус в пароль, если пользователь уже
  исправляет другие данные.
- Прежняя защита от одновременных запросов и тайм-аут сохранены.

Добавлены регрессии: шесть серий по шесть кликов в одной точке, разные
неверные пароли, очистка через существующее подключение ввода, успешный
повторный вход, редактирование почты до ответа сервера. Причина полного
зависания браузерного ввода ещё не воспроизведена в этой среде; изменения
исправляют конкретные дефекты формы, а результат требует проверки на Mac.

## Установка

1. Остановите запущенный Flutter клавишей q в его терминале.
2. В терминале VS Code, в папке moy_prihod, выполните:
   python3 /путь/к/fix_moy_prihod_input_connection.py
   Удобно набрать python3 и пробел, затем перетащить скачанный файл в терминал.
3. Выполните отдельно:
   flutter analyze
   flutter test
4. Запустите приложение:
   flutter run -d chrome --profile --web-port=8080 --dart-define-from-file=config/development.json

Установщик проверяет версии файлов и создаёт резервную копию.
Настройки Supabase, SMTP, база данных и config/development.json не меняются.

## Проверка на Mac

- Выйти из аккаунта. Неверный пароль → ошибка; поле можно очистить.
- Ввести правильный пароль и нажать Enter → экран приложения без обновления.
- Повторить вход кнопкой «Войти».
- После открытия использованной ссылки вернуться ко входу и повторить.
- При зависшем запросе поля доступны, через 30 секунд можно повторить запрос.
- Регистрация с подтверждением по-прежнему открывает экран ожидания письма.

В файле регрессионных проверок восемь Flutter-тестов. Предыдущие 81 тест
и анализатор прошли на Mac пользователя до этого обновления. В среде подготовки Flutter SDK
нет: проверены синтаксис Dart и установка/повторная установка/резервная копия,
но flutter analyze и flutter test должен выполнить пользователь на Mac.

После установки нового исправления сначала открыть обычный localhost:8080
без input_check=1 и повторить: удалить один символ → Войти → вернуть символ.
Проверить автозаполнение, ручной ввод и несколько быстрых кликов мышью.

Если понадобится новый диагностический отчёт, повторно запустить
check_moy_prihod_input.py перед запуском Flutter: сведения о файлах в диагностике
снимаются при установке этого скрипта. Не отправлять пароли, токены или Payload.

Для этой версии локально проверяются формат/синтаксис Dart, сохранение импортов,
совместимость с тремя хешами из отчёта пользователя и обратимое обновление файлов.
Flutter SDK в среде подготовки отсутствует: flutter analyze, flutter test и
воспроизведение в Chrome пока не выполнены. Исправление требует проверки на Mac.
