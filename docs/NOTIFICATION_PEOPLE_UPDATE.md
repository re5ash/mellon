# Mellon — пользователь в уведомлениях и переход в «Роли»

Вместо безличного уведомления появляется карточка конкретного пользователя: имя и фамилия, email, дата рождения, телефон (если указан), дата регистрации, клуб и состояние заявки. Данные не обрезаются; карточка и кнопки подстраиваются под ширину и размер текста. Новая регистрация появляется после подтверждения email, как в существующей системе проверки пользователей.

Кнопка **«Роли»** открывает существующее модальное окно сразу на выбранном человеке. **«Открыть заявку»** ведёт к заявке именно этого пользователя в нужном клубе. Если клуб приёма ещё не настроен, суперадмин видит каждого ожидающего пользователя отдельно и может открыть «Роли» или настройку приёма заявок.

Уведомления поступают через существующую подписку на изменения базы. Уже созданные заявки не теряются: SQL-обновление связывает известные уведомления с людьми и восстанавливает карточки текущих заявителей. Старые общие уведомления без надёжной связи с человеком сохраняются в истории базы и скрываются из списка, чтобы не дублировать новые карточки.

## Установка

1. Скачайте `update_mellon_notification_people.py` в «Загрузки». Если запущен `flutter run`, остановите его клавишей `q`.
2. Выполните в терминале:

```bash
cd ~/Desktop/moy_prihod
python3 ~/Downloads/update_mellon_notification_people.py
flutter analyze
flutter test
```

3. Откройте Supabase → SQL Editor → новый запрос. Вставьте **весь** файл `mellon_notification_people.sql` и нажмите **Run**. Этот файл выполняется после уже установленного `mellon_guest_review.sql`. Повторный запуск того же файла безопасен.
4. После успешных проверок запустите приложение:

```bash
flutter run -d chrome --profile --web-port=8080 --dart-define-from-file=config/development.json
```

SQL также находится в проекте: `supabase/updates/notification_people.sql`. Установщик создаёт резервную копию изменяемых файлов и не перезаписывает неизвестные локальные изменения. Данные аккаунтов, существующие назначения ролей, чаты и настройки не сбрасываются.

## Права и проверка пользователя

Персональные данные загружаются отдельным запросом с проверкой владельца уведомления и текущих прав. Администратор клуба видит заявителей своего клуба, суперадмин — все доступные ему заявки, включая пользователей без выбранного клуба. Существующие руководители с правом рассмотрения заявок сохраняют доступ в своей области. Обычные участники, гости и администраторы посторонних клубов не получают эти данные.

Персональные поля не сохраняются в тексте уведомления или push-сообщении. Перед открытием «Ролей» доступ проверяется повторно. Смена аккаунта не позволяет показать запоздалый ответ, полученный для прежнего пользователя.

Новые роли не создаются. Открытие «Ролей» не назначает права и не принимает заявку автоматически. Пока пользователь ожидает проверки, сначала рассмотрите его заявку через **«Открыть заявку»**, затем назначайте клубную роль. Защита действует и для старого, и для нового метода сохранения ролей. После рассмотрения существующие правила изменения глобальных и клубных прав продолжают действовать; изменения одного клуба не затрагивают другой.

## Проверка

После первого запуска на Mac анализатор не нашёл замечаний; 208 Flutter-тестов прошли, один упал на экране шириной 320 px с увеличенным текстом. В тесте нажатие выполнялось сразу после `ensureVisible`, до кадра с обновлёнными координатами. Теперь перед нажатием тест ожидает перерисовку и проверяет `hitTestable()`. Проверки открытия конкретного человека и возврата из окна ролей сохранены.

Если обновление уведомлений уже установлено, скачайте `fix_mellon_notification_test.py` и выполните:

```bash
cd ~/Desktop/moy_prihod
python3 ~/Downloads/fix_mellon_notification_test.py
flutter analyze
flutter test test/notification_people_test.dart --reporter expanded
flutter test
```

Это исправление меняет только тест и инструкцию. Код приложения и SQL остаются прежними, повторно выполнять SQL из-за этого исправления не нужно. Первая установка обновления уведомлений по-прежнему требует SQL из раздела «Установка» выше.

Официальное описание Flutter: [`ensureVisible`](https://api.flutter.dev/flutter/flutter_test/WidgetController/ensureVisible.html) прокручивает к элементу, а [`pump`](https://api.flutter.dev/flutter/flutter_test/WidgetTester/pump.html) выполняет кадр, обновляющий отрисовку в тесте.

В среде подготовки выполнены 27 проверок на локальном PostgreSQL-движке PGlite: миграции и повторная установка, восстановление уведомлений, отдельные карточки разных пользователей, подтверждение email, права на персональные данные, открытие профиля в каталоге ролей, запрет обхода проверки, сохранение клубных ролей после одобрения, отзыв доступа и прежняя логика клубов. Рабочая база Supabase при этих проверках не изменялась.

Добавлены Flutter widget-тесты в `test/notification_people_test.dart`: данные карточки, узкий экран и увеличенный текст, открытие нужного человека, точная ссылка на заявку, отсутствие клуба, отзыв доступа, повтор после ошибки и смена аккаунта во время запроса. Существующие Flutter-тесты не изменены. Flutter SDK в среде подготовки отсутствует: `flutter analyze` и `flutter test` необходимо выполнить на вашем Mac.
