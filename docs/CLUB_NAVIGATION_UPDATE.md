# Mellon: единый вход и молодёжные клубы

## Установка на Mac

Скачайте `update_mellon_club_navigation.py` и `mellon_club_navigation.sql` в папку «Загрузки». Остановите запущенный Flutter клавишей `q`. В терминале выполните:

```bash
cd ~/Desktop/moy_prihod
python3 ~/Downloads/update_mellon_club_navigation.py
flutter analyze
flutter test
```

Установщик проверяет совместимость файлов до записи, создаёт резервную копию рядом с проектом и сохраняет настройки подключения. Если он сообщает о несовместимой версии, пришлите полный вывод; не заменяйте файлы вручную. Повторный запуск безопасен.

Затем откройте свой проект Supabase → SQL Editor → New query, вставьте **весь** файл `mellon_club_navigation.sql` и нажмите Run. Это обновление 018. Оно требует ранее установленного обновления администратора клуба 017. Если SQL сообщает об отсутствующем обновлении 017, сначала выполните `supabase/updates/club_administrator.sql` из проекта, затем повторите 018. SQL выполняется транзакционно, повторный запуск не меняет данные.

После успешных проверок и SQL запустите:

```bash
flutter run -d chrome --profile --web-port=8080 --dart-define-from-file=config/development.json
```

## Что изменилось

- В профильном меню остались настройки, вход/выход и доступное пользователю управление. «Моя молодёжка» и «Все приходы» убраны.
- «Войти» открывает существующее окно сразу в режиме входа. Регистрация и восстановление пароля переключаются в нём же. Храм, непрерывная анимация облаков, размеры и стили сохранены.
- Общая регистрация создаёт аккаунт без автоматического выбора клуба и без скрытой подачи заявки. После входа пользователь выбирает клуб. Если email требует подтверждения, сначала показывается соответствующее сообщение.
- Список клубов содержит поиск, описание, статус собственной заявки, «Открыть клуб» или «Подать заявку». Административных кнопок в нём нет. После рассмотрения заявки можно нажать «Обновить список».
- Раздел «Приходы» убран из доступной навигации. Старые ссылки на приходы открывают список клубов, старые административные ссылки — раздел управления.
- Создание, редактирование и архивирование клубов находятся в «Управление → Молодёжные клубы» и доступны только суперадмину. Запрет действует и для прямого вызова старого или нового серверного метода.
- Руководители, администраторы и модераторы клуба сохраняют существующие инструменты для работы с его контентом, участниками и чатами в разделе управления. Это не даёт им права создавать или архивировать сами клубы.
- В окне «Роли» остаются «Всё приложение» и «Молодёжный клуб». Используется существующий каталог ролей. Гость доступен только глобально, с предупреждением об ограничении доступа без удаления аккаунта. Назначение в выбранном клубе не сбрасывает остальные права.
- Для одобрения заявки в клуб больше не требуется отдельное вступление в приход. Заявки в разные клубы независимы; повторная отправка того же запроса не создаёт дубликат.

Существующие аккаунты, роли, назначения, участники, клубы и контент не удаляются. Внутренние связи с таблицей `parishes` сохранены для совместимости данных и политик доступа; пользователь не выбирает приход. Новый клуб создаётся с городом и собственной технической связью хранения.

## Проверка поведения

1. Гость открывает ленту и карту; «Войти» в профильном меню показывает знакомое окно входа поверх текущего экрана.
2. Вход → регистрация → восстановление переключаются без перезапуска фона. Успешный вход открывает выбор клуба.
3. Участник видит клубы без административных кнопок; может подать заявку, затем обновить список после одобрения.
4. Суперадмин открывает «Управление → Молодёжные клубы», создаёт клуб и редактирует описание. Пользователь и локальный администратор этого пункта не видят.
5. В «Роли» изменение роли в клубе А сохраняет клуб Б и глобальный доступ. Гостя нет среди клубных ролей.
6. Проверьте узкий экран, увеличенный текст, выход из аккаунта и повторный вход.

## Проверки при подготовке

- 12 интеграционных сценариев нового SQL в локальном PostgreSQL-совместимом PGlite: авторизация, ограничения RPC, идемпотентность, сохранность назначений, независимые заявки, приём без прихода, архивирование и каталог.
- 29 сценариев каталога ролей и 19 сценариев управления правами проходят с текущими миграциями.
- Изменённые Dart-файлы отформатированы и проверены синтаксическим парсером. Добавлены и актуализированы widget-тесты модального входа, выбора клубов, регистрации без клуба и доступа к управлению.
- Flutter SDK в среде подготовки отсутствует: `flutter analyze`, `flutter test` и проверка интерфейса в Chrome должны быть выполнены на Mac. Это не заменяется проверкой синтаксиса или SQL.
- Исправления ввода пароля, основной контроллер входа, его регрессионные тесты и файл анимации фона не менялись.
