# Mellon — каталог ролей и радиокнопки

## Установка

Это обновление устанавливается поверх управления ролями. Скачайте `update_mellon_role_catalog.py` в «Загрузки», остановите приложение клавишей `q` и выполните:

```bash
cd ~/Desktop/moy_prihod
python3 ~/Downloads/update_mellon_role_catalog.py
flutter analyze
flutter test
```

Установщик проверяет версии файлов до записи, создаёт резервную копию рядом с проектом, сохраняет локальную конфигурацию и допускает повторный запуск. Включены предыдущие исправления загрузки окна ролей и тестов навигации.

В Supabase откройте **SQL Editor → New query**, вставьте **полностью** файл `mellon_role_catalog.sql` и нажмите **Run**. В проекте тот же файл находится в `supabase/updates/dynamic_role_catalog.sql`. Выполните его после ранее установленного `mellon_role_manager.sql`. Старое обновление повторять не требуется. Новый SQL не создаёт роли и не переименовывает существующие. Повторное выполнение этого же файла безопасно.

При установке миграций через Supabase CLI вместо SQL Editor используйте `202609120016_dynamic_role_catalog.sql` штатным способом. Выберите один способ установки.

После успешных проверок и SQL запустите:

```bash
flutter run -d chrome --profile --web-port=8080 --dart-define-from-file=config/development.json
```

## Изменения интерфейса

Сохранена структура: список людей и поиск слева, карточка выбранного человека справа, одна основная кнопка «Сохранить изменения» внизу. Светлая тема получила молочный фон, белые карточки, голубые акценты, тонкие рамки и мягкие тени. Тёмная тема также поддерживается. На узком экране список и карточка сменяются внутри того же окна. Длинные имена и названия переносятся, содержимое прокручивается.

Выбор роли оформлен радиокнопками. В каждом блоке можно выбрать одну роль. Для групп используется штатный [RadioGroup Flutter](https://api.flutter.dev/flutter/widgets/RadioGroup-class.html), поддерживающий навигацию клавиатурой. Отдельный переключатель подтверждения гостевого ограничения не является выбором роли.

## Откуда берутся роли

Названия и ключи загружаются из существующего серверного каталога при открытии карточки человека. В коде экрана больше нет перечисления доступных ролей. Изменение названия или добавление роли через существующие средства управления каталогом не требует переписывания окна: при повторном открытии карточки появятся актуальные данные.

| Блок | Источник и действие |
| --- | --- |
| Всё приложение | Все существующие записи каталога с глобальной областью действия. Выбор меняет только глобальные назначения этого аккаунта. |
| Молодёжный клуб | Роли клубной области из каталога; доступность назначения проверяется для выбранного клуба и текущего управляющего. |
| Обычное участие в клубе | Используется уже существующая базовая роль зарегистрированного пользователя. Внутри клуба этот выбор означает членство без дополнительных клубных назначений и не меняет глобальный доступ. |

Названия показываются именно как в каталоге. Например, если там записано «Суперадминистратор» или «Пользователь», окно использует эти названия. Обновление не вводит новые роли и не меняет их разрешения. Гость не предлагается как клубная роль. Блок прихода не добавляется.

Суперадмин видит всех зарегистрированных пользователей; большой список загружается страницами с кнопкой «Показать ещё». Руководителям доступны только люди и изменения в пределах их существующих полномочий. Недоступные назначения видны отключёнными, сервер также запрещает их выполнение.

## Сохранение

Переключение между клубами сохраняет черновой выбор в каждом из них. Запрос отправляет только изменённые блоки. Одна транзакция проверяет все изменения и сохраняет их вместе. Другие клубы, глобальные права при изменении только клуба, статус актива и профиль остаются прежними.

Если старые средства управления выдали несколько прямых ролей в одном блоке, окно сообщает об этом и предлагает выбрать одну. Замена происходит только при явном выборе и сохранении этого блока. Обновление не объединяет и не удаляет назначения массово. Ранее выданные права более широкой области продолжают действовать; клубное назначение не отменяет их.

Защита последнего действующего суперадмина, проверка смены аккаунта, подтверждение гостевого ограничения и безопасный повтор запроса сохранены. Если каталог или права изменились, пока карточка открыта, сервер отклонит устаревшее сохранение. Выбор остаётся на экране; кнопка загрузки актуальных прав позволяет продолжить.

## Проверка после установки

1. Откройте «Управление → Роли» под суперадмином, найдите человека и выберите его.
2. Проверьте названия из своего каталога: глобальные — в верхнем блоке, клубные — после выбора клуба.
3. Выберите разные роли в двух клубах. При возврате к первому его выбор должен сохраниться. Сохраните и откройте карточку заново.
4. Измените только роль второго клуба: первый клуб и глобальная роль должны остаться прежними.
5. Проверьте длинные названия и узкое окно браузера. Кнопки и текст должны оставаться доступными при прокрутке.
