# Управление чатами и каналами

Обновление для установленной версии с новым меню прихода, на которой пользователь подтвердил `flutter analyze: No issues found` и 51 прошедший Flutter-тест. Восемь прежних миграций сохраняются. Добавляется **202609100009_chat_administration.sql**.

## Установка на Mac

1. Скачайте `update_moy_prihod_chat_admin.py`.
2. Откройте **терминал VS Code** в проекте `moy_prihod`. Если Flutter запущен, нажмите `q` и дождитесь командной строки.
3. Напечатайте `python3` и пробел, перетащите **новый скачанный файл** из Finder в терминал и нажмите Enter. Скрипт запускается из папки проекта, файл может оставаться в «Загрузках».
4. После сообщения об установленном обновлении, в том же терминале:

```bash
flutter analyze
flutter test
```

5. Если обе проверки успешны, примените новую миграцию:

```bash
npx supabase db push
```

В списке должна быть только `202609100009_chat_administration.sql`. Подтвердите её применение и дождитесь `Finished supabase db push`.

6. В том же терминале запустите приложение:

```bash
flutter run -d chrome --web-port=8080 --dart-define-from-file=config/development.json
```

Полный bootstrap повторять не нужно. Установщик сохраняет конфигурацию подключения, зависимости, Android runner, локальные настройки и `docs/VERIFICATION.md`. Перед изменением файлов создаёт резервную копию рядом с проектом; при неизвестной версии исходников ничего не записывает. В случае конфликта пришлите вывод установщика.

## Создание первого чата — в приложении, в Chrome

1. Откройте верхнее меню **⋮ → Управление**.
2. Выберите **Тестовый приход → Чаты и каналы → Создать чат или канал**.
3. Заполните:

| Поле | Для первого чата |
|---|---|
| Название | Болталка |
| Описание | Свободное общение прихожан |
| Тип | Групповой чат |
| Иконка | Общение |
| Порядок в списке | 10 |
| В архиве | Выключено |

4. Нажмите **Сохранить чат**, затем откройте **Mellon → Чаты**. Новый чат должен появиться в меню.
5. Для «Объявлений» создайте ещё одну запись с типом **Канал объявлений**, иконкой «Объявления» и порядком 20.

Остальные разделы создаются так же. Названия и иконки можно менять; меньшее значение порядка поднимает чат в меню. Панель управления использует страницы по 20 записей со стабильным курсором по UUID; порядок в ней может отличаться от пользовательского меню.

## Поведение и права

- Список, создание и редактирование доступны при `chats.manage` для конкретного прихода. Название роли не проверяется в Flutter: разрешения расширяемые. Новое право не вводится, используются существующие назначения `parish_admin` и `super_admin` и пользовательские роли.
- В групповом чате отправка требует права `chat.send`; в канале — `channels.publish`. Права на управление комнатами сами по себе не дают право публикации. Обычный участник читает доступные ему каналы, но не видит поле отправки.
- Каждый серверный RPC проверяет сессию и область прав. `p_expected_user` сверяется с `auth.uid()`, а автор создания берётся только из сессии. Прямые клиентские INSERT/UPDATE комнат отозваны.
- Новая комната доступна участникам своего прихода (`access=parish`). У прежних закрытых комнат при редактировании сохраняются `restricted` и список приглашённых. Редактор приглашений пока не добавлен.
- Переключатель «В архиве» скрывает комнату из меню и блокирует отправку. Сообщения сохраняются. Чтобы восстановить комнату, откройте её в управлении, выключите переключатель и сохраните.
- Сохранение блокирует повторное нажатие. Повтор запроса после потери ответа использует тот же UUID, а редактирование проверяет ревизию. При конфликте введённый текст остаётся в форме; скопируйте его, вернитесь к списку, обновите и откройте актуальную запись.
- Смена аккаунта сбрасывает черновик. После успешного сохранения обновляются списки и сведения о чате. При изменении прав/архива другим администратором сервер применяет их при следующем запросе; кнопка «Обновить чат» обновляет и интерфейс.

Цвета и карточки меню прихода сохраняются. Показываются реальные описания и выбранные иконки. Автоматическое создание 13 комнат, вымышленные счётчики, картинки и сообщения не добавлены.

## Проверки и ограничения

В среде подготовки прошли **124 SQL-проверки**: 64 базовые, 19 управления приходами, 20 профиля и 21 управления чатами. Тесты используют PostgreSQL/PGlite с тестовой `auth.uid()`, а не живые JWT/PostgREST/Realtime. Новые проверки покрывают чужой приход, отзыв прав, каналы, архив/восстановление, повтор запроса, конфликты, приглашения, курсоры, аудит и запрет прямой записи. Отчёт: `chat-administration-test-results.txt`.

Установщик и полный архив прошли 12 проверок: совместимость, резервная копия, повторный запуск, конфликты, сохранение локальных настроек и откат после ошибки записи.

Dart проверен разбором синтаксиса и проверкой относительных импортов. Добавлены Flutter-тесты формы, отказов, повторного сохранения, смены аккаунта, адаптивности, прав отправки и реальных маршрутов. **Flutter SDK в среде подготовки отсутствует: analyze/test нового обновления запускаются на вашем Mac.** 51 успешный тест относится к версии до обновления.

Текущий каталог показывает до 50 доступных комнат, чат — последние 50 сообщений. История с пагинацией, авторы и время сообщений, непрочитанные, вложения и редактор приглашений остаются следующими этапами. Проверка Safari/PWA проводится на реальном iPhone через HTTPS.

## Ручная проверка

- Создайте «Болталку» и «Объявления», проверьте их меню и порядок.
- Измените описание и иконку, обновите страницу; данные должны сохраниться.
- Отправьте сообщение участником в группу. В канале у участника без `channels.publish` не должно быть поля отправки.
- Уберите группу в архив, проверьте запрет отправки, восстановите и убедитесь, что сообщение осталось.
- В другом аккаунте без административных прав раздел управления чатами должен быть недоступен, в том числе по прямой ссылке.

Следующий шаг после этих проверок — показывать авторов/время сообщений и добавить загрузку более ранней истории чата.
