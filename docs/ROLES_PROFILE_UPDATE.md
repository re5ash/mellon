# Роли, молодёжки, чаты и профиль

Обновление от 12 сентября 2026 года. Установщик рассчитан на версию после исправления ввода пароля (85 тестов на Mac), а также на подготовленную версию с новым разделом оформления. Если оформление ещё не установлено, оно входит в это обновление. Исправленные форма входа, контроллер входа и регрессионные тесты авторизации сохранены.

## Установка

1. Остановите работающий `flutter run` сочетанием Ctrl+C.
2. В Supabase → SQL Editor откройте новый запрос, вставьте **весь** файл `moy_prihod_roles_profile.sql`, нажмите Run. Скрипт требует уже установленные миграции 001–009 текущего приложения. Он добавляет структуру молодёжек, права, закрепы, данные профиля и закрытое хранилище аватаров. Применение атомарное; повторное выполнение того же файла безопасно. Если Supabase показывает ошибку, остановитесь и сохраните её текст.
3. Скачайте `update_moy_prihod_roles_profile.py` в «Загрузки», выполните:

```bash
cd ~/Desktop/moy_prihod
python3 ~/Downloads/update_moy_prihod_roles_profile.py
flutter pub get
flutter analyze
flutter test
```

4. Для первой установки всего набора примените отсутствующее обновление заявок `supabase/updates/club_applications.sql`, затем `supabase/updates/role_manager.sql`. Для ранее установленной версии применяйте только отсутствующие обновления по порядку. После успешных проверок запустите:

```bash
flutter run -d chrome --profile --web-port=8080 --dart-define-from-file=config/development.json
```

Установщик проверяет известные версии файлов, сохраняет резервную копию рядом с проектом и откатывает запись при сбое. Он не отправляет SQL в Supabase, не меняет ключи, конфигурацию окружения, письма авторизации или сохранённую диагностику ввода. При неизвестных изменениях он остановится до записи файлов. Самостоятельно заменять такие файлы не нужно.

Альтернатива для проекта с настроенным Supabase CLI: применить миграции `202609120010`, `202609120011`, `202609120012` обычным процессом миграций. Используйте один способ применения: SQL Editor либо CLI.

## Где находятся функции

- **⋮ → Настройки → Профиль**: фото, отображаемое имя, имя, фамилия, дата рождения, телефон, Email, приход и молодёжка. Редактирование сведений — в карточке профиля; Email меняется отдельным подтверждением через Supabase Auth.
- **⋮ → Моя молодёжка**: чаты, новости, календарь с выбором дня. Для гостя — «Присоединиться». Во время вступления в приход показывается форма личных данных.
- **⋮ → Управление → Роли**: единое окно участников и прав доступа. Глобальные настройки и клубы открываются отдельно. Конструктор ролей больше не предлагается.
- **Управление → нужный приход**: клубы, публикации, чаты и события. Назначения людей открываются через единое окно «Роли».
- **Моя молодёжка → Управление молодёжкой**: доступные руководителю или модератору действия.

Чтобы создать молодёжку: откройте управление нужным приходом, выберите «Молодёжки прихода» → «Создать молодёжку». Затем откройте «Роли», выберите человека, нужный клуб и «Руководитель», сохраните изменения. Новые названия ролей не создаются.

## Матрица доступа

| Уровень | Область | Основные действия |
|---|---|---|
| Суперадмин | Всё приложение | Приходы, молодёжки, назначения и определения ролей, контент, чаты, сообщения, глобальные настройки |
| Ранее назначенный админ прихода (не предлагается в новом окне) | Свой приход и его молодёжки | Структура, публикации, чаты, события, роли и участники |
| Руководитель | Своя молодёжка | Участники, модераторы, актив, публикации, чаты, события, закрепы и удаление любых сообщений |
| Модератор | Своя молодёжка | Закрепить/открепить, удалить сообщения, создать/редактировать события; без удаления событий и создания чатов по умолчанию |
| Участник | Своя молодёжка и разрешённые чаты | Читать, писать в групповые чаты, удалять свои сообщения |
| Гость | Публичные разделы | Общая лента, новости, публичные события, карта, приходы; присоединение через вход и заявку |

«Актив» — отдельный флаг членства, а не роль. При создании молодёжки автоматически создаётся закрытый чат «Актив». Его видят актив, руководители и администраторы с полномочиями управления этой областью. Статус актива сам по себе не даёт модераторских прав. После миграции 0015 человек может состоять в нескольких клубах независимо от членства в приходе. Настройки «Актив» и роли хранятся отдельно в каждом клубе.

**Приём в молодёжный клуб:** после миграции 0014 новая регистрация создаёт заявку в выбранный клуб и ожидающее вступление в приход. Право `youth.requests.review` позволяет руководителю рассматривать заявки только своей молодёжки. Перед принятием нужны подтверждённый email и одобрение вступления в приход его администратором. Подробности — `docs/CLUB_REGISTRATION_SCENE.md`.

Право `chats.create` выделено отдельно. Редактор с `chats.manage` не получает создание автоматически для новых ролей. Существовавшим до этого обновления пользовательским ролям управления чатами создание сохранено. Делегирование ограничено областью и собственным набором полномочий назначающего. Последнего суперадминистратора снять нельзя.

## Чаты

Удерживайте сообщение на телефоне или нажмите правой кнопкой мыши в браузере. Меню показывает только доступные действия. После подтверждения удаления и успешного ответа сервера пузырь плавно исчезает, а переписка сдвигается на его место. Надпись «Сообщение удалено» и пустой промежуток не остаются. Удаление закреплённого сообщения также снимает закреп. В аудите сохраняется действие, но не удалённый текст.

Компактная карточка закрепа находится сверху. Нажатие загружает нужную часть истории и прокручивает к сообщению, даже если оно старше последних 50. Кнопки «Более ранние сообщения» и «К новым сообщениям» переключают окна истории. Высота сообщений определяется текстом, без вычисления позиции по фиксированной высоте строки.

Права проверяются PostgreSQL при каждом действии. Открытый чат также обновляет доступ раз в 20 секунд и после возвращения в приложение. Новые сообщения и закрепы обновляются через Realtime; старый участок истории дополнительно перепроверяется вместе с доступом. При смене аккаунта редакторы и управление закрывают прежние данные.

## Профиль и фото

Личные имя/фамилия, дата рождения и телефон находятся в закрытой таблице и доступны только владельцу через проверяемые RPC. Отображаемое имя используется в сообщениях и управлении участниками. Email читается из Auth; изменение требует подтверждения по письмам. При включённой безопасной смене Email Supabase требует подтверждение старой и новой почты.

Фото: JPG, PNG или WebP до 5 МБ. Хранилище `profile-avatars` закрыто, файл принадлежит владельцу профиля. Для показа создаётся временная ссылка. Замена не перезаписывает предыдущий файл: сначала сохраняется новая ссылка в профиле, затем удаляется старый файл. После потери ответа сети возможно появление неиспользуемого файла, но используемое фото не удаляется автоматически. Очистка таких файлов — отдельная будущая служебная задача.

Для Chrome дополнительные разрешения платформы не нужны. Если позднее запускать именно приложение macOS, в его entitlements понадобится `com.apple.security.files.user-selected.read-only` для выбора файла. Нативные платформенные проекты и сборка телефона в это обновление не входят.

## Проверки

В среде подготовки прошли 144 проверки PostgreSQL через PGlite: прежние тесты доступа, управления, чатов и профиля, а также новые сценарии изоляции молодёжек, делегирования, модерации, закрепов, актива, аватаров и отзыва прав. Auth и схема Storage в этих тестах заменены контролируемыми моделями; это не проверка живого Supabase, Realtime по сети или параллельных соединений.

Проверены синтаксис/формат Dart и установщик: обе известные версии, повторная установка, резервные копии, отказ при неизвестных правках и восстановление после ошибки записи. Добавлены widget-тесты меню, подтверждения удаления, старого закрепа и узкого экрана.

**Flutter SDK здесь отсутствует. `flutter analyze`, `flutter test` и визуальный запуск обновлённых экранов в Chrome нужно выполнить на Mac.** До этих проверок нельзя считать браузерный сценарий подтверждённым. Автоматические тесты регистрации и исправления ввода пароля не изменены.

После установки проверьте две разные молодёжки и аккаунты руководителя/модератора/участника. Участник не должен видеть чат актива до выдачи статуса, а модератор — управлять соседней молодёжкой. Затем проверьте создание события, закреп старого сообщения, удаление с отменой подтверждения, смену фото и сохранение профиля после перезагрузки.
